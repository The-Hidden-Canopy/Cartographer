# Instanced component work and exact picking identity

The real-strand canid ear study exposed three coupled limits. Its 600 instances of 32 closed fibers retain small shared meshes, but its 1,657,792 visible-instance triangles exceeded the old 262,144 scene limit. Increasing the scene allowance exposed the 256-draw limit. Increasing draws then exposed the optimized path's numeric float24 picking token: high draw ordinals exceeded exact integer precision and readback refused the frame.

The shared CPU/native scene allowance is now 4,194,304 triangles. Native material draws are independently limited to 4,096. Two such ears plus the existing 260,600-triangle contextual head fit this work envelope arithmetically; a combined head rendering has not been validated by this change. The 64 MiB geometry bounds, per-mesh primitive bound, pixel/attachment limits, texture residency and staging limits remain independent admission gates.

Optimized PBR stores the integer draw/primitive token as bits of a positive normal float in the existing HDR alpha channel. Adding `0x00800000` before `asfloat` keeps the token above the subnormal range and avoids flush-to-zero. The 16-bit primitive field remains intact. Host readback and GPU motion preparation decode the same bits and validate them against the actual owner-built draw and face ranges. Display and temporal resolve preserve this opaque token; material failures remain negative and background remains zero. No additional render target or readback attachment is introduced. Reference-mode picking retains its separate numeric draw/primitive channels.

Temporal preparation now shares identical face-ID ranges across instances while retaining the existing 131,072-word face table bound. Expanded face work is separately capped at the scene allowance. The history digest binds both resident table contents and each draw's range assignment, so rebinding a draw to an existing range still invalidates source history. Source/session ownership, candidate generations, failed-preparation preservation and identity64 remain enforced.

**Capability gained / boundary improved.** Dense instanced component work is admitted without discarding strand geometry. Picking can retain high draw ordinals and the complete primitive field, and temporal identity data shares repeated instance ranges. Tests exercise exact work limits, one-item overflows, previous-target recovery, unchanged sources, shared face-table capacity, stale/foreign commits and rebinding to an already resident face range. Capacity fixtures use explicit requested work rather than deriving smaller fixtures from the implementation limit.

**Governance preserved.** No authored project, material catalog or journal is mutated by rendering. Project fixtures use the existing native transaction/journal route. No RegOS state transition, business-domain event, permission/org scope or human approval boundary changes. The user explicitly requested fuller fur, Cartographer repair and a raised budget. Code and boundary changes follow actual refusal evidence; invalid faces, resource overflows and invalid picking data continue to fail closed.

**Tests run.** The CPU scene-boundary executable passed; `ear_round_bundles_v24_CPU_ADMISSION.json` proves the current executable is identical to that recorded passing binary. Shader compilation in all authoring modes and temporal preparation tests passed (2/2, 7.18 seconds). Native GPU geometry/picking, native temporal integration and temporal kernel parity passed (3/3, 112.17 seconds): the geometry test covers exact 4,194,304 triangles, exact 4,096 draws, each one-item overflow, nearest-object picking above draw 255, primitive 65,536, unchanged source, unchanged geometry-memory overflow and previous-frame recovery; native temporal covers 17 lifecycle cases; kernel parity covers 10 numeric cases. Host preparation covers 4,096 draws sharing identity64 data, four million expanded faces within the unchanged 512 KiB table, overflows and history invalidation when a draw switches to an already resident range. The actual rounded-fur ear also rendered front/oblique/side at 2048 square, resolved to 512 square: 1,657,792 instance triangles, 11 shared fur meshes, 7,756,080 cold geometry-upload bytes and zero warm geometry uploads. Independent assembly-space checks cover all 19,200 strand roots (248.093–519.227 micrometres below the scaled skin; maximum native/checker difference 7.16e-18 metres). All current model files remain exact and the temporary model journal was retired with intent/result events. Photographic acceptance, final mirrored/export/head adoption and live desktop verification remain pending; these engine checks do not imply them. Per-stage code/executable identities, earlier failures and exact output are retained in `ear_round_bundles_v24_*` receipts in the canid study.

**Tests not run.** RegOS backend/state/permission suites, IDA training tests and frontend npm suites do not exercise these Cartographer paths and were not run. Full cross-device coverage, full application regression, final ear-pair/head mounting and game admission remain pending. The focused GPU checks include unchanged geometry-cache overflow and recovery tests; the broader GPU viewport suite is not yet rerun in full.

**Risks / rollback.** Worst-case admitted instance work and draw count increase sixteenfold, and CPU reference rendering can be slow. Independent memory and descriptor gates can still refuse a scene. Consumers need a rebuild. This private GPU identity encoding must change consistently in fused PBR, host readback and the motion producer. Restore this bounded source diff to return to 262,144 triangles, 256 draws and the prior encoding; retain the separate earlier geometry-cache repair. Current retained models remain unchanged, so no model restoration or migration is needed for that rollback.

**Rejected options.** Reducing fur to fit the former scene cap; removing overflow checks; extending numeric float IDs beyond their exact range; increasing geometry/image budgets with the work limit; allocating another picking render target; sharing face storage without binding per-draw assignments; or treating a successful technical preview as photographic acceptance. Hardware batching remains a possible performance improvement, independent of this bounded correctness change.

**Cross-product trace / promotion.** RegOS, IDA_Training, hidden_canopy_bot and Ask_IDA have no direct changes, shared API/schema changes, dataset/training changes or deployments. The native picking transport is private, not a `.carto` schema change. Capability progress is scoped to the tested renderer gates; promotion progress remains pending hardware verification and actual component review.
