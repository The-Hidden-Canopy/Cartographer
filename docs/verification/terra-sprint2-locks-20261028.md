# Sprint 2 — mesh-instance lock boundary

- Claim: session `01a18315-0b59-77d3-8777-a1ba96798919` per dispatch; requested model `gpt-6.1-terra` (runtime model not independently exposed). Worktree is detached at `fae4f7d95259ba38e79edc94ae12275df4161cd4`. Source-observed finding, not a runtime reproduction.
- Finding: `SetProjectSelectedVertexPositionCommand` and `ExtrudeProjectSelectedFaceCommand` build revision-bound mesh edits without checking the selected object's lock; their shared-mesh owner scan is conditional on multiple selected groups. A single selected object could therefore write the mesh of a locked owner or locked sibling. Command undo and redo use the same project mesh mutation methods.
- Repair: `ProjectDocument::replace_mesh_if_revision` now rejects any current locked object referencing the target asset before document replacement, receipt publication or revision bump. `replace_mesh`, vertex patch, and all 13 persistent topology patch families route through it; this also applies to their command undo/redo and transaction replacements. Unattached meshes and unrelated unlocked assets remain editable. The private checkpoint rebase merge and step-selection paths copy mesh state directly, so they now check current/base scene locks respectively before copying. These checks do not change schema, source registry, geometry algorithms or audit ownership.
- Invariants: failing guarded replacements do not change persisted geometry, source bindings, project/mesh revisions, patch or topology receipts. Component commands stage multi-owner operations on a candidate before swap. ProjectDocument does not own journal/history; integration must prove command failure keeps both unchanged, including journal failure and redo/undo interactions. Undo of an edit now explicitly refuses if a referencing object becomes locked until it is unlocked; this is intentional lock semantics.
- Import compatibility: `ImportGltfSceneCommand` creates mesh assets via `insert_mesh` then attaches newly inserted objects; source registry reimport uses `apply_source_reimport_plan` and does not itself replace geometry. Those paths are not modified. Any source-reimport or prefab operation that actually replaces an already attached mesh now refuses if any affected instance is locked; it must report failure and leave its existing transaction/candidate unpublished, not silently override locks. No runtime importer/reimport claim is made.
- Caller/history handoff: the central guard checks *current* scene objects bound to the asset being written, covering locked selected owners and shared siblings as long as their mesh binding is still current. `SetProjectSelectedVertexPositionCommand::AppliedMeshEdit` and `ExtrudeProjectSelectedFaceCommand::AppliedMeshEdit` retain the asset but not the original owner. On redo their cached edit branch checks mesh revision only; if the original selected object was removed or rebound to another mesh, the project boundary cannot recover that original identity. History/integration owner should retain the selected object ID per edit and revalidate existence, expected object-to-mesh binding and its lock before redo (and decide/document equivalent undo identity checks), while still using the central shared-instance scan. This is a source-observed remaining caller contract, not fixed here; no claim that stale-owner replay is closed.

It uses test-only private access and a deliberate no-revision lock injection to model a lock change after selection/history; it does not assert that lock injection is an authorized production action.
