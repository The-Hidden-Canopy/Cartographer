# Evaluated sculpt mesh export

The desktop standard mesh exporter materializes an installed SculptPreviewProvider's identity-preserving evaluated positions into a transient copy of the saved source mesh. It checks vertex IDs, triangle indices, face IDs, and edge mappings before applying a bounded atomic position patch; the materialized copy must recompile to the same topology. It does not change the project or authored mesh. If the provider is absent, fails, changes topology, or the resulting mesh is invalid, export is refused rather than writing source geometry as though sculpt were included. OBJ, PLY and STL use their existing exporters and format-specific limitations still apply.

The scene glTF/GLB exporter still consumes the saved document and cannot incorporate sculpt. It refuses any document containing a sculpt stack, including hidden or unused stacks, rather than silently omit deformation. This is conservative, not evaluated glTF support. A future scene export implementation needs an explicit evaluated-scene path and attribute, material, instance and persistence verification.

Validation in an isolated CMake consumer on 2026-11-14: a public mock-provider test checks source preservation, evaluated OBJ round-trip and topology-change rejection. A separate private harness checks the real provider from authored point and sampled surface strokes, save/reopen, evaluated OBJ round-trip and layer visibility. Both CTest cases passed. Desktop main compiled with and without the provider macro using Clang 22.1.8/LLVM-MinGW and the Vulkan desktop compile settings. The modified provider-enabled Vulkan desktop compiled and linked in the isolated build. It has not been installed or interactively exercised; no physical pointer or visual export acceptance is claimed. Full repository suite was not run.
