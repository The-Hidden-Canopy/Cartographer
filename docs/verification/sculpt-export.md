# Evaluated sculpt mesh export

The desktop standard mesh exporter materializes an installed SculptPreviewProvider's identity-preserving evaluated positions into a transient copy of the saved source mesh. It checks vertex IDs, triangle indices, face IDs, and edge mappings before applying a bounded atomic position patch; the materialized copy must recompile to the same topology. It does not change the project or authored mesh. If the provider is absent, fails, changes topology, or the resulting mesh is invalid, export is refused rather than writing source geometry as though sculpt were included. OBJ, PLY and STL use their existing exporters and format-specific limitations still apply.

The desktop glTF/GLB route evaluates every stored sculpt stack with the installed provider, then supplies document- and stack-digest-bound, revision-bound position-only patches to the scene exporter. The exporter applies patches to transient source copies and preserves the saved document, topology, UVs, material assignments, and hierarchy. Missing, stale, unknown or incomplete products fail before artifact publication. Changed sculpt fails closed when authored corner normals/tangents or aging appearance could be stale; those combinations need rebaking or explicit normal handling. Editable strokes are not included in glTF/GLB and the report says so. A build without the evaluator refuses scenes containing sculpt rather than exporting the base mesh.

Validation in an isolated CMake consumer on 2026-11-14: a public mock-provider test checks source preservation, evaluated OBJ round-trip and topology-change rejection. A separate private harness checks the real provider from authored point and sampled surface strokes, save/reopen, evaluated OBJ round-trip and layer visibility. Both CTest cases passed. Desktop main compiled with and without the provider macro using Clang 22.1.8/LLVM-MinGW and the Vulkan desktop compile settings. The updated glTF/GLB exporter and provider-enabled Vulkan desktop compiled and linked in the isolated Debug build; no native visual acceptance is claimed. The earlier provider-enabled Vulkan desktop compiled and linked in the isolated build. It has not been installed or interactively exercised; no physical pointer or visual export acceptance is claimed. Full repository suite was not run.

2026-11-14 follow-on: isolated public mock-provider and private real-provider tests both passed save/reopen → evaluated glTF and GLB → reimport position checks. The public test also checks UV values and shared instances after reimport, missing/stale patch refusal including a layer-visibility-only change, authored-normal refusal, and preservation of an existing output on refusal. A separate multi-material/embedded-texture export/reimport regression passes for both formats. Both tests verify source document serialization remains unchanged. The modified desktop compiled and linked but has not been visually exercised. Full suite remains unrun.
