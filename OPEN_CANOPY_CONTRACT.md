# The Open Canopy Contract

Software should serve the person running it.

When The Hidden Canopy releases a project under the Open Canopy model, we make the following commitments to its users.

1. You do not need our permission to use it.

No account, registration, activation, subscription, license server, or recurring authorization is required to install and use the software.

2. What is open stays usable.

We will not deliberately move previously open, locally usable functionality behind a mandatory payment, account, cloud service, or artificial usage limit.

New commercial products and services may be built around an open project, but the existing open software remains open and functional.

3. Your software does not expire.

There are no remote kill switches, subscription expirations, artificial end dates, or periodic license checks required to continue using the software you already possess.

A copy that works today should not stop working tomorrow because The Hidden Canopy changed a server.

4. The internet is an option, not a requirement.

Features that inherently require a network may use one.

The application itself must not require an internet connection merely to launch, authenticate, edit local work, access local data, or perform functionality that can reasonably operate on the user's machine.

5. Your data belongs on your machine when you want it there.

Projects, configurations, histories, assets, and other user-created data must remain accessible locally.

Cloud storage may be offered as an option. It will not be the only practical way to access work created with the software.

6. We do not require surveillance as the price of using free software.

Telemetry, analytics, crash reporting, usage measurement, and similar data collection must be optional unless technically necessary for a service the user explicitly chooses to use.

Declining telemetry must not cripple the application.

7. Your work must be able to leave.

We will not intentionally restrict export, degrade exported files, hide essential project information, or create artificial incompatibilities for the purpose of locking users into The Hidden Canopy.

Where practical, we will support documented, interoperable, and widely usable formats.

8. Important formats will be documented.

The structures required to understand, preserve, migrate, or independently implement support for a project's primary files and data will be publicly documented.

A user should not need The Hidden Canopy's continued existence to understand their own work.

9. The source must be meaningfully buildable.

An open-source release should not merely expose code.

The documented build process must not secretly depend on private Hidden Canopy infrastructure, undisclosed internal services, proprietary credentials, or inaccessible components required for the software's ordinary open functionality.

10. Forks are legitimate.

The ability to study, modify, rebuild, maintain, and fork open software is not an accident or an inconvenience to us. It is part of the point.

If another community can preserve a project after we stop maintaining it, the system worked.

11. Commercial services will compete on value, not captivity.

The Hidden Canopy may charge for hosting, collaboration, support, integration, training, deployment, certified builds, enterprise administration, custom development, specialized infrastructure, or other services.

We will not intentionally make the open software worse merely to force users into those services.

Paid offerings should provide something worth paying for.

12. Your existing work will not become leverage against you.

A change in our business model, ownership, infrastructure, pricing, or strategy should not prevent you from opening, using, exporting, or continuing work that you created with an Open Canopy project.

13. Open means open even when it becomes inconvenient.

These commitments matter most after a project becomes successful.

Growth, investment, acquisition, enterprise demand, or commercial pressure are not reasons to quietly turn an open tool into rented permission.

If we want to build something proprietary, we can build something new.

We do not need to take back what we already gave the community.

---

## The principle

Download it. Run it. Study it. Change it. Build with it. Keep your work.

You should not need an ongoing relationship with The Hidden Canopy to keep using software we released for you to own.
